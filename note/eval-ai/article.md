# 評価コメントをAIに丸投げすると起きる3つの失敗と、防ぐための7つの指示文

部下の評価コメント、そろそろ生成AIに手伝わせたいと考えていませんか。

書くこと自体は、もう慣れているはずです。困るのは、量と時間です。部下が8人いれば、評価の締め切り前に8人分を書き上げることになります。

ただ、AIに任せる前に引っかかることもあるはずです。

「部下の名前や評価を、AIに入力していいのか」
「AIがそれらしい文章を作って、事実と違うことを書かないか」
「全員が同じような文章になって、手抜きだと思われないか」

この記事は、その3つの不安に答えるために書きました。

読み終えると、**部下の個人情報を入力せずに、事実にもとづいた評価コメントの下書きを生成AIで作る手順**が分かります。手順は、期中のメモの整理から、フィードバック面談の練習までの7ステップです。

この記事のやり方は、特定のAIサービスの裏ワザではありません。人事評価でよく知られた「評価エラー」の考え方と、生成AIが苦手なこと（事実をつくってしまうこと）への対策をもとに組み立てています。ChatGPT、Claude、Gemini、Copilotなど、どの生成AIでもそのまま使えます。

評価の時間を「作文」ではなく、「判断」に使うための記事です。

## 評価コメントに時間がかかるのは、なぜですか？

時間がかかる原因は、文章を書く作業ではありません。**半年分の事実を思い出して集める作業**に時間がかかっています。

評価コメントには、次の3つが同時に求められます。

- 半年分の具体的な事実
- 会社の評価基準との対応
- 部下が読んで納得できる言い方

ところが、日々の業務に追われていると、期中の記録はどうしても断片的になります。締め切り前に記憶をたどると、直近の出来事に偏りがちです。気をつけていないと、「9月の大きなトラブル」の印象で半年の評価が決まってしまうこともあります。

部下が8人いれば、この作業が8回続きます。1人あたり30分でも4時間です。後半になるほど集中力が落ち、コメントが似てくるのも自然なことです。

つまり、**事実を集めて整理する工程さえ仕組み化できれば、評価コメントの負担は大きく減ります。** この「整理」と「下書き」こそ、生成AIが最も得意とする作業です。

## 生成AIに「丸投げ」すると、何が起きますか？

結論から言うと、丸投げは危険です。「部下の評価コメントを書いて」とだけ頼むと、次の3つの失敗が起きやすくなります。

**失敗1：やっていない実績を、それらしく書いてしまう**

生成AIは、情報が足りないと「ありそうな内容」で文章を埋めようとします。「主体的にチームを巻き込み」のような、実際には確認していない表現が混ざります。部下が読めば「この上司は自分を見ていない」とすぐに気づきます。

**失敗2：部下の個人情報を、そのまま入力してしまう**

氏名、社員番号、評価ランク、健康や家庭の事情。どれも慎重に扱うべき情報です。会社によっては、生成AIへの入力を規程で制限していることもあります。

**失敗3：全員が同じようなコメントになる**

同じ指示で8人分を作ると、言い回しがそろってしまいます。「コピペされた評価」に見えると、評価への信頼そのものが下がります。

どの失敗も、AIの性能が原因ではありません。**渡す情報と、指示の出し方の問題です。** 逆に言えば、指示文を整えるだけで3つとも防げます。

## 失敗しないためのルールは何ですか？

失敗を防ぐルールは3つです。

**ルール1：入力する前に匿名化する**

氏名は「Aさん」、取引先は「X社」のように置き換えます。評価ランクそのものも、必要な場面以外では入力しません。

**ルール2：事実だけを渡し、「書いていないことは書かない」と指示する**

AIには、メモにある事実以外を書かせないようにします。根拠が足りない項目は「根拠不足」と表示させます。これで失敗1をほぼ防げます。

**ルール3：評価を決めるのは人、AIは整理と点検を担当する**

AIに評価ランクを決めさせてはいけません。あなたが決めた評価に対して、AIは「根拠と合っているか」「評価エラーがないか」を点検する役に回します。

たとえば、「Aさんは期待以上（B+）」と決めたとします。AIには「この評価とメモの事実に矛盾はないか」だけを確認させます。判断はあなた、点検はAI、という分担です。

この3つのルールを、毎回ゼロから考えるのは大変です。そこで、**コピーして穴埋めするだけで3つのルールが守られる指示文**を7つ用意しました。

## この記事の有料部分では、何が手に入りますか？

有料部分では、期中のメモから面談の練習までを、7つの指示文（プロンプト）で順番に進めます。

1. 入力前の匿名化チェックリスト（コピーして使える置き換え表つき）
2. 指示文①：バラバラの期中メモを、評価項目ごとに整理する
3. 指示文②：あなたが決めた評価と、事実の矛盾を点検する
4. 指示文③：評価エラー（直近の出来事への偏り、印象による引っ張られなど）を点検する
5. 指示文④：「事実→評価→期待」の型で、評価コメントを下書きする
6. 指示文⑤：部下の自己評価とのギャップを整理し、面談で聞く質問をつくる
7. 指示文⑥：言いにくい評価を伝える、フィードバック面談の台本をつくる
8. 指示文⑦：AIに部下役を演じてもらい、面談を練習する
9. 入力例と出力例（想定例）を、ステップごとに掲載
10. 提出前の最終チェックリスト（10項目）

**こんな方に向いています**

- 部下が3人以上いて、評価コメントを毎期まとめて書いている
- 生成AIを使ってみたいが、情報の扱いが不安で踏み出せていない
- 「評価に納得してもらえない」面談をなんとかしたい

**向いていない方**

- 評価ランクまでAIに決めてほしい方（この記事では扱いません）
- 会社の規程で、業務での生成AI利用が禁止されている方

なお、生成AIを業務で使う前には、必ず会社の利用ルールを確認してください。匿名化をしていても、社外のサービスに入力してよい情報の範囲は会社ごとに異なります。

## 入力する前に、何をどう匿名化すればいいですか？

匿名化の基本は、**「その文章だけを第三者が読んでも、誰のことか分からない状態」にすること**です。次の置き換え表を使ってください。

| 元の情報 | 置き換え方 | 例 |
|---|---|---|
| 部下の氏名 | アルファベット | 田中さん → Aさん |
| 自分・同僚の氏名 | 役割 | 鈴木課長 → 私、佐藤さん → 隣の課のリーダー |
| 取引先・顧客名 | アルファベット＋業種 | ○○商事 → X社（卸売） |
| 社内プロジェクト名 | 一般名詞 | Project Phoenix → 基幹システム刷新案件 |
| 正確な金額 | 割合・規模感 | 売上3,214万円 → 目標比112% |
| 日付 | 月単位 | 7月14日 → 7月中旬 |
| 健康・家庭・信条などの事情 | **入力しない** | — |
| 評価ランク | 必要な指示文②でのみ使う | — |

最後の2行は特に大切です。健康状態や家庭の事情は、評価コメントに書くべき内容でもありません。AIに渡す必要もありません。

**入力前の30秒チェック**

- 氏名、社名、プロジェクト名が残っていないか
- 「○○部で唯一の女性リーダー」など、属性から本人が特定できる書き方がないか
- コピーしたメールやチャットの署名欄が残っていないか

## 指示文①：期中メモを評価項目ごとに整理するには？

最初の作業は、メモ、日報、チャットの記録など、バラバラの材料を評価項目ごとに仕分けることです。**この段階では文章を書かせません。** 整理だけを頼みます。

```
あなたは人事評価の準備を手伝うアシスタントです。
以下の【期中メモ】を、【評価項目】ごとに分類してください。

# ルール
- メモに書かれている事実だけを使うこと。推測や補足で事実を追加しないこと
- 1つの事実が複数の項目に当てはまる場合は、最も関係の深い項目に入れること
- どの項目にも当てはまらない事実は「その他」に入れること
- 事実が1つもない項目は「根拠不足」と表示すること
- 出力は表形式（評価項目／事実／時期）にすること
- 最後に、時期の偏り（特定の月に事実が集中していないか）を一言でコメントすること

# 評価項目
（例：業績目標の達成／業務品質／チームへの貢献／主体性・改善提案）
ここに自社の評価項目を貼り付け

# 期中メモ（Aさん・対象期間：4月〜9月）
ここに匿名化したメモを貼り付け
```

**使い方のコツ**

メモは箇条書きで十分です。「5月中旬：X社への提案資料をほぼ一人で作成、受注」のように、時期と事実が分かれば足ります。

最後の「時期の偏り」のコメントが重要です。「事実の8割が8〜9月に集中しています」と出たら、4〜7月の記録を思い出す合図です。

## 指示文②：自分が決めた評価と事実の矛盾を点検するには？

評価ランクは、指示文①の表を見ながら、**あなた自身が先に決めてください。** そのうえで、AIに矛盾の点検だけを頼みます。

```
あなたは人事評価の点検担当です。評価を決める権限はありません。
評価者がつけた【仮の評価】が、【整理済みの事実】と矛盾していないかを点検してください。

# ルール
- 新しい評価ランクを提案しないこと
- 各評価項目について「根拠が十分」「根拠がやや弱い」「矛盾の可能性あり」のどれかで判定すること
- 「やや弱い」「矛盾の可能性あり」の場合は、理由を1〜2文で示すこと
- 判定の根拠には、必ず【整理済みの事実】の該当行を引用すること
- 評価基準の文言と事実の対応が曖昧な箇所があれば、評価者に確認すべき質問として挙げること

# 評価基準（グレードの定義）
ここに自社の評価基準を貼り付け

# 仮の評価
業績目標の達成：B+（期待をやや上回る）
業務品質：B（期待どおり）
……

# 整理済みの事実
ここに指示文①の出力表を貼り付け
```

「矛盾の可能性あり」と出ても、評価を変える必要があるとは限りません。メモに書き漏れた事実があるだけ、ということもよくあります。その場合は事実を追記して、もう一度点検してください。

## 指示文③：評価エラーがないかを点検するには？

評価エラーとは、評価者が無意識に陥りやすい判断の偏りのことです。人事評価の研修でよく扱われる代表的なものを、AIに点検させます。

```
あなたは人事評価の公正さをチェックする担当です。
以下の【評価メモ】に、次の評価エラーの兆候がないかを点検してください。

# 点検する評価エラー
1. 期末誤差：評価期間の終わりごろの出来事に、評価が引っ張られていないか
2. ハロー効果：1つの目立つ長所・短所が、無関係な項目の評価にまで影響していないか
3. 寛大化・厳格化：根拠に比べて、全体的に甘すぎる・厳しすぎる表現になっていないか
4. 中心化：判断を避けて、すべてが「普通」「標準」にそろっていないか
5. 人格への言及：行動や成果ではなく、性格や人柄を評価していないか
6. 属性への言及：年齢、性別、家庭の状況など、評価と無関係な属性に触れていないか

# ルール
- エラーの兆候がある場合は、該当箇所を引用し、どのエラーに当たるかと理由を示すこと
- 兆候がない項目は「問題なし」と1行で示すこと
- 断定せず「〜の可能性があります」と表現すること
- 最後に、評価者が自問すべき質問を3つ挙げること

# 評価メモ
（指示文②の結果と、あなたが下書きしたメモや所感を貼り付け）
```

**部下が複数いる場合の使い方**

全員分の「仮の評価」を一覧にして貼り付け、「チーム全体で寛大化・中心化の傾向がないか」も点検させると効果的です。全員が「B」にそろっていたら、それ自体が見直しのサインです。

## 指示文④：評価コメントを下書きするには？

ここで初めて文章を書かせます。型は **「事実→評価→期待」** の3段構成です。事実から入ると、部下は「ちゃんと見てもらえている」と感じやすくなります。

```
あなたは、部下の成長を本気で応援する上司の文章を下書きするアシスタントです。
以下の材料をもとに、【評価項目】ごとの評価コメントを下書きしてください。

# 構成（各項目で必ずこの順番）
1. 事実：具体的な行動や成果を1〜2文で示す（時期や数字があれば入れる）
2. 評価：その事実を、評価基準に照らしてどう評価したかを1文で示す
3. 期待：次の期に期待する行動を、具体的に1文で示す

# ルール
- 【整理済みの事実】にない出来事や数字を書かないこと
- 「頑張った」「意欲的」など、事実の裏付けがない抽象語だけで終わらせないこと
- 性格や人柄ではなく、行動と成果について書くこと
- 1項目あたり【120〜160字】、です・ます調
- 語調：【率直だが温かい／丁寧で落ち着いた】から選ぶ
- 下書きの最後に、事実が不足していて書けなかった箇所を「要確認」として列挙すること

# 評価項目と確定した評価
ここに貼り付け

# 整理済みの事実
ここに指示文①の出力表（必要なら追記済みのもの）を貼り付け
```

**コメントが似てしまうのを防ぐコツ**

部下ごとに、「この人の今期を一言で表すと何か」を先に一行だけ書き、指示文の冒頭に足してください。たとえば「Aさん：守りから攻めに転じた半年」「Bさん：品質の土台をつくった半年」です。この一行があるだけで、文章の軸が人ごとに変わります。

## 指示文⑤：部下の自己評価とのギャップを整理するには？

面談で揉めやすいのは、評価そのものよりも、**本人の自己評価と上司の評価のズレ**です。ズレを事前に整理しておけば、面談で慌てずに済みます。

```
あなたは評価面談の準備を手伝うアシスタントです。
【部下の自己評価】と【上司の評価】を比べ、ギャップを整理してください。

# 出力形式
1. 評価が一致している項目（一言ずつ）
2. ギャップがある項目：表形式（項目／本人の見方／上司の見方／ズレの原因として考えられること）
3. 面談で本人に聞くべき質問：ギャップのある項目ごとに2つずつ
   - 本人を責める質問ではなく、本人の見方を理解するための質問にすること
   - 「はい／いいえ」で終わらない質問にすること

# ルール
- どちらの評価が正しいかを判定しないこと
- ズレの原因は、断定せず「〜の可能性」として複数挙げること

# 部下の自己評価（匿名化済み）
ここに貼り付け

# 上司の評価
ここに指示文④の下書きを貼り付け
```

「ズレの原因として考えられること」には、上司側の見落としも含まれます。**本人のほうが正しい事実を知っている可能性**を、面談前に意識しておくことが大切です。

## 指示文⑥：言いにくい評価を伝える面談の台本をつくるには？

期待を下回った評価や、本人の自己評価より低い評価を伝える場面の台本です。台本といっても、読み上げるためのものではありません。**話す順番と、詰まったときの言葉を準備しておくためのもの**です。

```
あなたは、評価面談の進め方に詳しいマネジメントの相談相手です。
以下の情報をもとに、30分の評価フィードバック面談の台本を作成してください。

# 台本の構成
1. 冒頭（2分）：面談の目的を伝える一言
2. 本人の振り返りを聞く（8分）：最初に聞く質問と、深掘りの質問
3. 良かった点を伝える（5分）：事実にもとづいて
4. 評価と、期待との差を伝える（8分）：事実→評価→理由の順で
5. 次の期の目標をすり合わせる（5分）
6. 締め（2分）

# 特に厚く準備してほしいこと
- 【本人が納得していない様子のとき】に使える言葉を3つ
- 【本人が黙ってしまったとき】に使える言葉を3つ
- 言ってはいけない言葉の例と、その言い換え

# ルール
- 人格を否定する表現、他の社員との比較は使わないこと
- 評価の結論をあいまいにぼかさないこと（結論は明確に、伝え方は丁寧に）

# 伝える評価と、そう判断した事実
ここに貼り付け

# 自己評価とのギャップ
ここに指示文⑤の出力を貼り付け
```

ポイントは、最後のルール「結論は明確に、伝え方は丁寧に」です。言いにくさから評価をぼかすと、部下は「結局どうすればよかったのか」が分からなくなります。

## 指示文⑦：AIを相手に面談を練習するには？

最後は練習です。AIに部下役を演じてもらい、指示文⑥の台本で実際に話してみます。

```
これから評価面談のロールプレイをします。
あなたは部下のAさんを演じてください。私は上司です。

# Aさんの設定
- 自己評価：ここに貼り付け
- 今回の評価に対する本音：【納得していない／不安を感じている／黙りがち】から1つ
- 話し方の特徴：（例）結論を言わずに経緯から話す

# ルール
- Aさんとして、1回の発言は2〜4文で返すこと
- 私の言葉が一方的・あいまい・威圧的だと感じたら、Aさんとして自然に反発や沈黙を示すこと
- 私が「ここで終了」と入力したら、ロールプレイをやめて、上司としての私の話し方を次の観点で講評すること
  1. 事実にもとづいて話せていたか
  2. 本人の話を聞く時間を取れていたか
  3. 結論が明確に伝わっていたか
  4. 次の行動が具体的に合意できたか
- 講評は、良かった点を1つ、改善点を2つ、改善後の言い方の例を2つ示すこと

準備ができたら、Aさんとして「失礼します」から始めてください。
```

本音の設定を「納得していない」に変えて、2回練習するのがおすすめです。本番で最も緊張する場面を、先に一度経験しておけます。

## 実際の入力と出力は、どんなイメージですか？（想定例）

以下は、架空の部下「Aさん」を想定した例です。実在の人物や実績ではありません。

**指示文①に入れる期中メモ（想定例）**

```
- 4月下旬：新人Bさんの OJT 担当に。週1回の振り返りを自主的に設定
- 5月中旬：X社（卸売）向け提案資料をほぼ一人で作成。6月に受注
- 6月：月次レポートの集計ミスが2回。いずれも提出前に私が発見
- 8月上旬：集計手順のチェックリストを自作し、チームに共有
- 9月：四半期売上 目標比112%
```

**指示文④の出力例（業務品質の項目・想定例）**

> 6月に月次レポートで集計ミスが2回ありましたが、8月上旬には集計手順のチェックリストを自ら作成し、チーム全体に共有してくれました。ミスを個人の反省で終わらせず、仕組みで再発を防いだ点を評価し、業務品質は「期待どおり」としました。次の期は、チェックリストの運用状況を月に1度見直し、チームのミス件数の変化を数字で示してくれることを期待しています。

ミスの事実を隠さず、その後の改善行動を評価し、次の期待を数字で示しています。メモにない「主体的に」「意欲的に」といった言葉は使っていません。これが、指示文のルールが効いている状態です。

## 提出前に何を確認すればいいですか？

AIの下書きは、あくまで下書きです。提出前に、次の10項目を確認してください。

- [ ] コメント内の出来事は、すべて実際にあった事実か
- [ ] 数字や時期は、元の記録と一致しているか
- [ ] 匿名化した名前（Aさん、X社など）を、正しい表記に戻したか
- [ ] 性格や人柄ではなく、行動と成果について書いているか
- [ ] 年齢、性別、家庭の状況など、評価と無関係な属性に触れていないか
- [ ] 評価ランクとコメントの温度感が合っているか（B評価なのに絶賛していないか）
- [ ] 期待する行動が、次の期に実行できるほど具体的か
- [ ] 他の部下のコメントと、言い回しが似すぎていないか
- [ ] 本人が読んで、「どの場面のことか」が分かるか
- [ ] 自分の言葉として、面談で口に出して説明できるか

最後の項目が、いちばん大切です。**説明できない文章は、どれだけ整っていても削除してください。** 評価コメントの責任は、AIではなく評価者にあります。

## まとめ：今期の評価から、何を始めればいいですか？

この記事のポイントを振り返ります。

- 評価コメントに時間がかかる原因は、文章ではなく「事実集め」
- 生成AIへの丸投げは、架空の実績、個人情報、似たコメントの3つの失敗を生む
- 守るルールは「匿名化」「事実以外を書かせない」「評価は人が決める」の3つ
- 7つの指示文で、整理→点検→下書き→面談準備→練習までを順番に進める
- 提出前の10項目チェックで、最後は自分の言葉にする

まずは部下1人分だけ、指示文①でメモを整理するところから試してみてください。表になった事実を見るだけでも、評価の見え方が変わるはずです。
